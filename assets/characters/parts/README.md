# The parts data

Every character part in the game lives in this directory: eight JSON files,
101 parts, about 1.7 MB of ASCII. **Nothing here is written by hand.** It is
generated by `tools/parts_author/`, and the way to move a voxel is to change
the Python and re-run:

    python3 -m tools.parts_author

## Why it is here and not in `scripts/`

Habit 1 in `CLAUDE.md`: *facts as data, not prose in code.* An ASCII voxel is
a fact. It used to be 33,158 lines of `const` dictionaries under
`scripts/character/parts/`, which Godot compiled at load, `git` could not
usefully review, and every grep of `scripts/character/` paid for. Nothing
about the format was wrong. Its address was.

## The schema

One file per module, named for the module: `human`, `elf`, `dwarf`,
`lizardfolk`, `hair`, `gear`, `armour`, `critter`. `PartsData.module()` reads
them, converts `size` to a `Vector3i` and `anchor` to a `Vector3`, and hands
back a read-only dictionary in exactly the shape `VoxelModel.parse()` and
`Rig.build()` have always taken.

```json
{ "schema": 1, "generator": "tools/parts_author/human.py", "res": 96,
  "doc": ["The stocky human, voxel by voxel, at 1/16 of a block.", "..."],
  "parts": {
    "head": { "size": [27, 32, 26], "anchor": [13.5, 0.0, 13.76470588235294],
              "notes": {"8": "the mouth"},
              "doc": ["18 wide, 22 tall, 16 deep PLUS ONE for the nose."],
              "slices": [["..........", "..."], ["..."]] } } }
```

- **`schema`** — 1. `PartsData` refuses to load anything else, loudly.
- **`generator`** — which module under `tools/parts_author/` wrote this file.
- **`res`** — the output grid, 96 model voxels to a 2.00 m human. The
  generators author at 64 and `voxlib` scales once, at output; see the
  comment above `voxlib.U`.
- **`doc`** — the module's prose, one line per line. **The loader ignores it.**
- **`parts`** — the only key the loader reads. Keys are the name a bone table
  refers to a part with: `head`, `jerkin_human`, `hand_r`. Hair has no such
  map — its options are positional, in `PartsHair.HAIR` — so its keys are the
  constants' names, lowercased: `human_hair_short`.

And inside a part:

- **`size`** — `[w, h, d]`, three ints. **JSON numbers parse as floats in
  Godot**, so `PartsData` casts each one with `int()` before building the
  `Vector3i`. Miss that and `Vector3i(...)` takes a float and nothing about
  the failure names this file.
- **`anchor`** — `[x, y, z]`, three floats: the part's pivot, in its own
  index space. May sit on a half voxel.
- **`slices`** — bottom-to-top, each slice front-to-back, each row one
  character per voxel across. `VoxelModel.parse()` walks this array and
  nothing reshapes it on the way in. The convention — which character is which
  slot, and why the first character of a row is the character's *right* — is
  documented once, on `VoxelModel`.
- **`notes`** — slice index (as a string, because JSON keys are strings) to
  the note the author left on it: `"8": "the mouth"`. **Ignored by the
  loader.**

`doc` and `notes` are the `#` comments the old GDScript carried, and they are
kept because they are the only documentation this art has. They cost about 3%
of the bytes.

## Rows are wrapped, deliberately

Several rows to a line, at the same width the GDScript used. That is not
`json.dumps` output and it is not accidental: the ASCII rows *are* the art,
and the only review this art gets is somebody reading a `+`/`-` in a diff. A
row is never merged with the next one, so a moved voxel shows up as one
changed row.

## Replacing a part

This is not the drop-in path. `assets/characters/<race>/<part>.vox` still
replaces a part with a model, with no code change — see the README one
directory up. The difference now is what it replaces: a part loaded from
JSON, under the same name, which is the key in `parts` above.
